🧠 How I Approach a Problem

I'm trying not to fall into the trap of immediately searching for the answer.

My usual process is:

1. Understand

Read the problem carefully and figure out exactly what is being asked.

2. Think

Try to come up with a solution myself before looking at other approaches.

3. Implement

Write the solution and test it against different cases.

4. Analyze

Understand:

Time Complexity
Space Complexity
Why the solution works
Edge cases
5. Learn

If my approach isn't optimal, I study better approaches and understand the underlying pattern.

6. Document

Push the solution here.

🔍 What I Want to Learn

I'm not just trying to memorize solutions.

I want to recognize patterns.

For example:

"Compare both ends"       → Two Pointers
"Find something in sorted data" → Binary Search
"Contiguous subarray"     → Sliding Window / Prefix Sum
"Repeated subproblems"    → Dynamic Programming
"Explore connected nodes" → BFS / DFS
"Need the largest/smallest K" → Heap


The long-term goal is to look at a new problem and think:

"I've seen this pattern before."
